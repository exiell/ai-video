# AniGuide · UI 设计提案（三选一）

> 这一轮只做方向和首屏，不改动现有 React 应用。三个方案都用同一份示例项目数据：林教头风雪山神庙，7 个镜头、28 / 40 秒、1 个必须修。

## 先看现状

用真实浏览器跑了一遍现在的应用，问题不在于“不好看”，而在于**它不像给纯新手用的**：

- 首页只有 24 个字，第一屏 38% 是一整块空白；h1 是品牌名，17px，真正的内容是两张卡和一张空表。
- 全站正文 13px，深色后台三栏；导航按“分镜 / 穿帮检查 / 角色设定 / 场景设定 / 提示词”平铺，用户得先理解模块，才能知道下一步点哪。
- 引导向导一屏只放一个问题，剩下约 70% 空白；分镜页一屏塞满禁用态、Key、参考图、批量生成和技术术语。
- 一个做视频的工具，界面上没有一张画面。7 个镜头只是 7 段表单。

## 三个方案都改的事

不管选哪个视觉方向，产品结构先改成用户能读懂的四步：

1. **故事** → 2. **角色与场景** → 3. **分镜** → 4. **交付**
2. 每个页面第一屏先回答三件事：**现在在哪、下一步做什么、为什么**。
3. 一屏只留一个主行动，最多两个次级行动。
4. 分镜带成为视觉主角：7 个镜头、每镜时长、当前镜的三拍（起点 / 唯一动作 / 终点）。
5. 检查结果按“必须修 / 建议看 / 仅供参考”分层，给预计时间，给直接跳转。
6. 所有数字统一口径：7 镜、28 / 40 秒、2 角色、2 场景、7 条连续性锁、1 个必须修。

## 方案 A · 制作手册

![A · 制作手册](./.taste-skill/A/desktop-fold.jpg)

- **视觉**：暖石色框架 + 纸白页面 + 墨黑 + 朱砂红；中文衬线标题（Noto Serif SC）+ 无衬线正文（Noto Sans SC）。
- **结构**：左边四步导航；中间是“下一步”黑卡、7 镜胶片带、第 6 镜三拍、故事一句话；右边是制作进度、检查、参考图。
- **气质**：像一本剧组工作手册，适合“想先读懂、再动手”的用户。
- **优点**：品牌感最强；文字读起来最舒服；“下一步”和“为什么”放在同一块里。
- **风险**：和现在的深色工具差异最大；需要引入中文衬线字体；信息密度中等。

## 方案 B · 放映室

![B · 放映室](./.taste-skill/B/desktop-fold.jpg)

- **视觉**：近黑背景 + 米白画面 + 黄铜色；深色只用来托画面，不靠边框。
- **结构**：左边场次；中间是当前镜头的大画面 + 底部胶片条 + 三拍；右边是“这一镜”的检查、提示词、已挂的锁、总时长。
- **气质**：像剪辑 / 看片台，适合视觉型用户，先看画面再改细节。
- **优点**：最像“在做视频”；镜头感强；长时间看不累。
- **风险**：对纯新手最不“教程化”；小字多；没有步骤提示，用户得自己知道去哪。

## 方案 C · 四步工作台

![C · 四步工作台](./.taste-skill/C/desktop-fold.jpg)

- **视觉**：浅灰蓝底 + 白卡 + 一个蓝色强调；14px 正文；14px 圆角。蓝色只落在当前步、进度和主行动上。
- **结构**：顶部四步进度（当前步淡蓝）→“今天从这里继续”→“接下来三件事”→“最近在做的镜头”+ 7 镜时长条 → 检查 / 参考图。
- **气质**：清楚、轻、像现代创作工具，最接近“新手照做”。
- **优点**：最容易理解；主行动和任务顺序明确；手机端最顺。
- **风险**：最像常见 SaaS，品牌辨识度弱于 A；需要靠真实画面和内容避免“模板感”。

## 怎么选

| 如果优先… | 选 |
| --- | --- |
| 新手第一次就能用、少解释 | **C** |
| 这个工具有自己的性格、像一件作品 | **A** |
| 先看画面、再改细节，用户偏视觉型 | **B** |

我的建议：**首版用 C 做全站结构**，因为目标用户是“完全新手”，四步进度和“接下来三件事”能直接降低第一次使用的门槛。A 的视觉语言可以留到品牌页或导出封面；B 更适合作为“分镜编辑”这一屏的专用视图，而不是全站首页。

## 手机端

三个方案都在 390px 单独排过：A 保留品牌条和主行动，B 把大画面放在最上，C 折叠成菜单 + 四步 2×2 + 下一步优先。截图在各自的 `.taste-skill/*/mobile-fold.jpg`。

## 说明

- 7 个镜头画面是**用代码画的示意帧**，不是生成图，也不是项目自有素材；落地时应换成用户真实生成的关键帧。
- 文案里的姓名、时长、检查数量来自内置示例项目；上线前要跟示例数据保持一致。
- 三个页面都是静态高保真稿，未接现有路由、状态和表单。选定方向后，再落到 `aniguide/src`。
- 三份稿都用同一套 inspector 在 1440 / 768 / 390 跑过，**0 个 FAIL**；剩余 WARN 是辅助小字（11–12px）和 A 的“图表无强调色”提示。
