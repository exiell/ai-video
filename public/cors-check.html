跨域实测工具

它只做一件事：在**你的浏览器里**发几个真实请求，把「浏览器能不能直连这几家模型厂商」这件事 问清楚。结论直接决定 AniGuide 要不要引入一个转发代理。

先说结论：这两家已经实测确认可以直连

在写这个页面之前，已经用服务端响应头做过一次实测（复现方式：node scripts/cors-probe.mjs）：

接口 预检 allow-origin 实际请求
DeepSeek 对话 200 回显 Origin 401
硅基流动 对话 / 文生图 204 * 401

401 反而是好消息：它证明请求真的到达了服务器并把业务错误码返回来了 （Token is invalid / Authentication Fails）， 不是被拦在网络层。既然响应带了允许跨域的头，浏览器就会放行。

所以：跨域这一关已经过了，AniGuide 不需要代理。 这个页面现在的用处变成了第二步——用你自己的 Key 验证「能不能成功返回内容」。

为什么这件事仍然值得你在浏览器里再跑一次

响应头是**服务端**说的话，跨域判定规则是公开确定的，所以那份证据已经很硬。 但仍有两点只有在浏览器里才能确认：

  1. 你的网络环境有没有额外的拦截（公司代理、防火墙、运营商）
  2. 带上真实 Key 之后，接口能不能真的返回内容——也就是余额、权限、模型名是否都对

填 Key（可选）

⚠️ Key 只留在本页面的输入框里，不写入任何存储、不发往除了厂商之外的任何地址。 关闭页面即消失。测完请关掉这个页面。

结果怎么看

  1. HTTP 200 拿到了模型回复 → 浏览器可以直连，AniGuide 用直连模式即可，不需要代理。
  2. 被跨域挡住（CORS） → 这家厂商没给浏览器开放接口。两条路：换一家可以直连的， 或者给 AniGuide 配一个转发代理。
  3. 401 / 403 / 402 → 跨域是通的，问题出在 Key 或余额上。这其实是好消息： 说明直连可行。
  4. 没填 Key 时的结果 → 看状态码就够了。返回 401 说明请求发出去了（跨域通过）； 如果连状态码都没有、直接报 Failed to fetch，那就是被跨域挡了。

测完怎么用这个结论

打开 AniGuide → 设置 → 模型接入：

  1. 本来就确认可直连，所以「代理地址」留空即可
  2. 把 Key 填进去，点「测试连接」——它区分「跨域被拦 / 密钥无效 / 余额不足 / 限流」并给出对应做法
  3. 万一你所在网络环境真的连不上，再填代理地址。网关会自动切换传输方式，业务代码零改动
