# AniGuide · AI 动漫视频创作向导

> 把「我想做个动漫视频」这个模糊念头，用问答引导的方式，变成**一份可以直接开拍的制作方案**。

AniGuide 是一个**免注册、纯网页**的工具。它不生成视频，也不做剪辑——它交付的是**方案**：动漫分镜表、角色与场景设定卡、可直接粘贴到多平台的提示词，外加一份穿帮检查单。

**它解决的是「我该做什么」，而不是「怎么做出来」。** 拿着 AniGuide 的产出，你去即梦、可灵、Seedance 等平台执行。

---

## 它解决什么问题

新手做 AI 动漫视频，卡在五个连续的坎上：

| # | 困境 | AniGuide 怎么解 |
|---|---|---|
| 1 | 搜了一堆教程全是软件操作，没人告诉我先干什么 | 问答式向导，一次只问一个问题，每步都解释「为什么问这个」 |
| 2 | 能讲故事，但不知道该用几个镜头、每个多长 | 分镜引擎，每镜强制回答：起点、唯一动作、终点 |
| 3 | 提示词不会写、各平台写法不同 | 一次生成多平台格式，英文正文 + 中文对照 + 逐项说明 |
| 4 | 角色和场景在每个镜头都不一样 | 五道一致性防线 + 穿帮检查单 + 自动修复 |
| 5 | 做完了不知道好不好 | 不给分数，给问题清单——报原因，不报错误码 |

## 它明确不做

一键成片 · 视频生成 · 配音字幕音乐 · 剪辑 · 自动发布 · 账号系统 · 云端存储 · 训练模型

> **本项目的护城河是「轻」，不是「全」。** 上面每一条都能做，但做了就不是新手工具了。

## 核心亮点

### 1. 五道一致性防线 —— 这是这类工具最容易翻车的地方

跨镜穿帮（角色变脸、衣服变色、场景换样）是 AI 动漫最劝退的问题，也是最难排查的。AniGuide 用五道防线叠加来压住它：

| 层 | 手段 | 解决的问题 |
|---|---|---|
| **连续性锁** | 你登记的英文短语被**原样写进**相关每一帧的提示词 | 能说清的特征：服装、道具、场地固定物 |
| **角色形象图** | 全身多视图 + 头部特写作为参考图传入 | 脸很难用文字描述，只能靠图；全身图里的脸只有几十像素，所以两张分开出 |
| **本镜首帧** | 后两帧自动拿本镜首帧当构图锚点 | 锁机位、景别、光线方向——形象图锁不住「这一镜怎么取景」 |
| **上一镜尾帧** | 仅在转场标为「承接」时用作跨镜锚点 | 两镜的空间、光线、主体位置真正接得住 |
| **场景参考板** | 空镜与广角镜头用它固定空间结构、固定元素与光线方向 | 同一个地方在不同镜头里不会像两个地方 |

**几个刻意做对的地方：**

- **跳切时绝不用上一镜尾帧。** 那会把两个不该相连的镜头强行焊在一起，同时毁掉两边。
- **外观始终写进提示词，不因为「有参考图」就省略。** 曾经试过「有图就不重描角色」，结果是一顶只写在身份描述里、没进锁的帽子，在相邻镜头之间凭空消失了。**该防的是「同一件事说两遍」（按逗号粒度去重），不是「把外观整个删掉」**——重复只是让模型在两个版本之间摇，缺失是让模型自己编。
- **顺序有意义。** 身份锁放提示词最前（放末尾会被后面的场景描述冲掉），而且**配件类锁排在面部类锁之前**——实测配饰比脸更容易丢。
- **输出画幅由最后一张参考图决定**，所以排序实际上是「谁说了算」的取舍，界面会把这个取舍显示出来。

### 2. 穿帮检查 + 自动修复（先看后改）

**25 条规则**，分「必须修 / 建议看 / 仅供参考」三档。每条都写清**为什么**，不是甩一个错误码。

检查的是**文本约束**——「该一致的地方有没有写下来」，不是「生成出来一定没问题」。它不承诺零穿帮，只承诺让大部分穿帮在花钱出图之前就暴露。

几条你会在意的规则：

| 规则 | 它在说什么 |
|---|---|
| 相邻镜同景别 | 连续两个中景，观众会觉得「没剪」 |
| 画面描述里的代词 | 提示词是给模型看的文字，它不知道「他」是谁——两人同框时用代词，动作一定错位 |
| 抽象情绪词 | 「难过」没法指导画面，模型只能从它见过的无数种里随便挑一种 |
| 单镜位移过大 | 几秒内主体跨越大段距离，中间那段运动最难补得自然 |

自动修复遵守两条铁律：

- **只提议能机械确定的修改**（补锁、补字段、统一时长）
- **需要审美判断的一律不碰**——光线冲突改成傍晚还是改场景卡？只有你知道。机器猜错会把创作意图改坏，而且你还不知道为什么

而且**只提议，不直接改**：每条都带修改前后的对照，逐条勾选确认后才落盘，并且能撤销。

> 有两条规则是**主动撤掉**的，原因写在代码里。最近一条是「镜头正文没提到场景固定元素」——它**在正常用法下必然误报**（中文描述配英文短语，字面永远匹配不上），而且固定元素本来就会被自动注入提示词，正文提没提不影响生成结果。**一个只会误报的规则，会训练用户忽略整份检查单。**

### 3. 8 个厂商开箱可用，一个厂商一个 Key

已实测确认浏览器可直连的厂商：DeepSeek、阿里云百炼（通义千问）、智谱 GLM、月之暗面 Kimi、MiniMax、阶跃星辰、硅基流动、百度千帆。

- **Key 是厂商级的**，不是模型级的——同一家的对话与出图共用一个 Key，只填一次
- 出图请求体按**字段映射**构造：MiniMax 的 `aspect_ratio`、硅基流动的 `image_size` 各按各家的写法，加一家只改数据不改代码
- 每家都写明**直连证据**（`POST 401 + ACAO` 之类），没实测过的如实标注「未核实」

### 4. 五条诚实规则

| 防线 | 具体做法 |
|---|---|
| 失败时给原始证据 | 模型输出解析失败时，把**模型原文**摊开给用户看，而不是只说「格式错误」 |
| 报原因不报代码 | 报「跨域被拦 / 密钥无效 / 余额不足 / 模型名不被接受」，各给对应做法 |
| 不静默修改 | 自动修复要确认；重生成要确认；保存失败会**当场说出来** |
| 能力边界如实说 | 没实测的标「未核实」，做不了的直接写「它明确不做」 |
| 量不准就不报 | 曾用「字面重合度」判断首尾差距，在示例项目上报 6 条**全是误报**，整条规则撤掉 |

### 5. 零后端 · 零注册 · 数据不出浏览器

所有数据存在浏览器的 IndexedDB 里。请求只在**你的浏览器 ↔ 模型厂商**之间发生，中间没有我们的服务器。

**API Key 默认存在这台电脑上**，下次打开不用重填。如果这台电脑是共用的，去设置里勾一下「不保存到本机」——那样 Key 只存在当前会话，关掉浏览器即失效，已经存下来的也会当场清掉。不论勾不勾，Key 都不会离开你的浏览器。

> ⚠️ 24 小时陷阱：阿里云返回的图片链接 24 小时后失效。AniGuide 在拿到图的**当下就下载留存**成 base64——你看到的每一张图都是真正属于你的。

### 6. 用一句话改稿：「问 AI」

右侧有一个可收起的对话栏。你可以直接说人话：

> 把结局改成主角牺牲
> 第 3 镜太平了
> 加一个反派，四十来岁的武官
> 删掉多余的第 5 镜

它不只是回答问题，而是**直接给出可执行的改动**：改字段、**新建**角色 / 场景 / 镜头、**删除**多余的对象。改情节牵动十几个镜头时，它一次性给全，不挤牙膏。

**它能看到穿帮检查的结果。** 检查引擎算出来的问题会进它的上下文，所以你问「哪里有穿帮」时，它报的是引擎的实际结论，不是自己读一遍的印象。

几条设计上的取舍：

- **一律先确认，不直接改。** 任何规模的改动都先列出来给你过目——这是创作工具，每条改动都直接决定要花钱生成的成品
- **可以整体撤销。** 撤销存的是改动前的完整快照，所以连删除也能还原
- **id 由程序生成，不让模型编。** 模型会编出重复或格式不对的 id，而这类错误界面上不一定看得见，却会让引用悄悄断掉
- **删除会级联清理引用**（清角色出场、把场景置空、重排镜号），否则会留下「这一镜谁出镜」显示空白而你不知道何故

### 7. 界面按「制作顺序」排，不是按模块排
新手打开工具时最想知道两件事：**现在到哪了、下一步做哪一件**。所以侧栏不是「分镜 / 检查 / 角色 / 场景 / 提示词」平铺，而是按你实际会走的顺序：

```
作品主页 → 故事 → 角色 / 场景 → 分镜 → 穿帮检查 → 提示词 → 导出
```

作品主页只回答三件事：现在到哪了、下一步做哪一件、后面还排着哪几件。**一屏一个主行动**，主行动用当前外观的主色，其余是白底按钮或文字链接。

分镜页第一屏先给你 7 个镜头本身，「用模型生成 / 批量生成」收进折叠区——工具不该挡在作品前面。

### 8. 三套外观，同一个工具

侧栏没有外观开关；统一在「设置 → 外观」里切换，选择存在本机。

| 外观 | 感觉 | 表面 |
|---|---|---|
| **工作台**（默认） | 浅、清楚 | 冷灰蓝底 + 白卡 + 蓝 `#2457d6` |
| **暗房** | 夜里剪片、长时间看画面 | 近黑 `#0b0d10` + 黄铜 `#d6a45e`，靠明度分层 |
| **蓝图** | 一份分镜档案 | 冷灰纸面 + 墨蓝 `#0b5578` + 坐标纸网格 |

三套共用同一套组件与布局，只换表面、字体和强调色——不会出现「某个主题少一个功能」。

所有动效都遵守 `prefers-reduced-motion`；下拉菜单是自研的 listbox，支持 ↑↓ / Home / End / Enter / Esc 和点外面关闭。

## 快速开始

### 第 0 步：把项目拿到手

有 git 的话，在你想放项目的目录里执行：

```bash
git clone https://github.com/exiell/ai-video.git aniguide
cd aniguide
```

> 仓库名是 `ai-video`，但项目叫 AniGuide —— 所以这里用 `aniguide` 作为本地目录名，看得顺眼些。不加也行，目录名随你。

**没装 git？** 在仓库页面点绿色的 **Code → Download ZIP**，解压后跳到下一步——效果一样。

后面的命令全部在**这个目录里**执行。

### 第 1 步：一键启动（推荐）

**Windows** —— 双击项目根目录的 **`start.cmd`**（就是刚才 clone 出来的那个目录）

**macOS / Linux** —— 在项目目录里执行：

```bash
chmod +x start.sh    # 只需一次
./start.sh
```

第一次运行会多花约 1 分钟装依赖，之后就快了。**装完浏览器会自动打开。**


### 一键脚本替你处理了什么

脚本会自动完成：找 Node.js（装在别的盘也能找到）→ 确保 pnpm（没有就用 corepack 或 npm 装）→ 按需安装依赖 → 起开发服务器并打开浏览器。

**它不只是省几条命令**，而是把新手最容易卡住的地方都处理了：

| 情况 | 脚本的行为 |
|---|---|
| 没装 Node.js | 给出下载地址，而不是抛一个看不懂的报错 |
| Node 版本太低 | 明确说「需要 20 或更高」，并说清怎么升级 |
| 没有 pnpm | 自动用 corepack 或 npm 装上，装不上才让你手动来 |
| 依赖已装过 | 跳过安装（比对 lockfile 哈希），不白等一分钟 |
| 端口被占用 | 提示可能已经开着一个了，问你要不要直接打开 |
| 项目在 OneDrive 等同步盘 | 提醒可能会崩（报 EBUSY），建议换目录 |
| 某一步失败 | **说清是哪一步、什么原因、下一步怎么办** |

> 唯一的前提是装了 Node.js。这一步没法自动做——静默安装软件是不礼貌的。

### 上手顺序

1. **先点「打开示例项目」** —— 不用配任何 API Key 就能看到一份完整产出长什么样。看完你就知道这些东西最终是为了什么。
2. 打开 `/cors-check.html`（设置页也有入口），确认你的网络环境能直连模型厂商。**跨域是浏览器的策略，命令行能通不代表浏览器能通。**
3. 去「设置 → 连接与 Key」按厂商填 Key，点「测试连接」——它会当场告诉你跨域被拦 / 密钥无效 / 余额不足 / 模型名不对。
4. 按侧栏从头走：**故事 → 角色 / 场景 → 分镜 → 穿帮检查 → 提示词 → 导出**。每一步顶部都有一行「下一步」，告诉你该去哪、点哪个按钮。
5. 卡住的时候用右侧的**「问 AI」**——说人话就行，它给出可执行的改动，你确认后才生效。

想换外观：**设置 → 外观**，三套里挑一个，选择会记住。

### 常用命令

```bash
./start.sh        # 一键启动（macOS / Linux；Windows 双击 start.cmd）
pnpm dev          # 开发服务器
pnpm test         # 跑测试（821 条）
pnpm test:watch   # 测试监听模式
pnpm build        # 生产构建 → dist/
pnpm typecheck    # 只做类型检查

# 一次性诊断脚本（需要联网）
node scripts/provider-probe.mjs   # 核验各模型厂商能否从浏览器直连
```

## 技术栈

| 用途 | 选型 | 为什么 |
|---|---|---|
| 构建 | Vite 6 + React 19 + TypeScript（strict） | 纯静态产物，可直接丢到任意静态托管 |
| 状态 | Zustand | 比 Redux 轻，够用 |
| 本地库 | Dexie（IndexedDB） | 要存图片 base64，localStorage 的几 MB 不够 |
| 校验 | Zod | 模型输出不可信，必须有运行时校验 |
| 打包 | fflate | 导出 zip，体积小 |

**没有 UI 组件库**，样式自己写——为了控制体积和保持观感一致。三套外观靠 `data-theme` 切换 CSS 变量，不换组件。

界面图标来自 [Tabler Icons](https://github.com/tabler/tabler-icons)（MIT），厂商标识来自 [Simple Icons](https://github.com/simple-icons/simple-icons)（CC0-1.0），蓝图外观的网格底纹参考 [css3patterns](https://github.com/LeaVerou/css3patterns)（MIT）。均为按许可引入的原始 SVG，未引入图标库运行时。

所有模型调用必须经过唯一入口 `ModelGateway`，业务代码不允许直接 fetch 厂商接口——这样将来要接代理，只改一处配置。

代码组织：

```
src/
  types/       数据模型（唯一真源，所有字段的含义都写在这里）
  domain/      纯逻辑：检查规则、提示词构造、图像规格、导出、帮助内容
  services/    模型网关（协议适配）、LLM 编排、出图、本地存储
  store/       Zustand 状态
  pages/       页面
  components/  组件
  assets/      图标 SVG（按许可引入的原始文件）
```

1. **项目设计文档** —— 了解设计取舍，避免重走已经走过的弯路（不随源码公开，需向维护者索取）
2. **`tests/`** —— 821 条测试里有相当一部分是**针对具体踩过的坑**写的，注释里写了当时的症状。它们不是形式，是护栏

提交前请跑一遍 `pnpm test` 和 `pnpm typecheck`，**两条都过才会被合并**。

### 三条硬性原则（细节在贡献指南里）

- **报原因，不报错误码。** 面向的是不懂技术的创作者：「密钥无效，可能是复制时少了几个字符」，而不是 `Error 401`。
- **不承诺做不到的事。** 没实测的标「未核实」，做不到的直说。
- **护城河是「轻」，不是「全」。** 加依赖、加抽象层之前先想想能不能不加。

### 动手前的一个提醒

改提示词和检查规则会涉及**大量文本替换**——这个项目早期就因为没有版本控制，一次字符串替换失手把文件改坏过，最后靠手工比对行号才修回来。

所以：**每改完一件小事就提交一次。** 用分支做实验也行，别让一整天的工作悬在一个未提交的工作区里。
